# Connected App identity runtime (opt-in)

This slice implements the unchanged `connected-app-identity-v1` introspection response in D1 and the source-only browser handoff. Browser login requires both `CONNECTED_APP_IDENTITY_ENABLED=true` and `CONNECTED_APP_TELEGRAM_BOOTSTRAP_ENABLED=true`; neither flag is configured in the deployed Worker. Do not enable it for end users yet.

Bindings:

- `CONNECTED_APP_HOST_KEY`: a separate random secret of at least 32 characters, held only by the trusted host backend. The host authenticates every select, issue, revoke and disable-principal request with `Authorization: Bearer`.
- `CONNECTED_APP_SERVICE_KEYS`: JSON map of exact `recruiting-web` and `crm-web` audiences to independent random service keys of at least 32 characters. The app backend authenticates introspection with its own key. These are not browser credentials.
- `CONNECTED_APP_ISSUER`: the expected HTTPS issuer URL.

The Agent-owned session authority supplies the current authenticated principal/profile/session and `profileGeneration` to the Connected App broker through `AgentProfileAuthority`. `POST /v1/connected-app-sessions/select` remains host-only and accepts a supplied tuple only when it matches the current authority result; `connected_app_memberships` rows are separate audience-specific app entitlements, not canonical Agent membership. Each CP selection/grant update increments a CP-local generation and records the Agent generation, invalidating old tokens. A different principal cannot take over an existing session ID. `POST .../issue` rechecks the current Agent session and takes `{sessionId,audience,scopes}`; it returns an opaque 256-bit token with a one hour lifetime. The host must keep it server side until a one-time browser code exchange exists. `POST .../revoke` takes `{token}`; `POST .../disable-principal` takes `{principalId}`. Both are host only. The audience service calls `POST .../introspect` with `{token,audience}` and receives the v1 active or inactive response, always with `Cache-Control: no-store`; an unavailable Agent authority produces HTTP 503 and no active response. Token hashes, never bearer values, are stored in D1.

The host credential authenticates the caller only. `src/agent-profile-authority/v1.ts` implements an opt-in Agent-owned authority module inside the supported Control Plane Worker, against namespaced D1 tables, and the connected-app broker consumes its typed port. Worker route and D1 tests cover the source behavior. Private reviewed identity provisioning and production gateway integration are not accepted or live, and migrations have not been deployed. Before activation, complete and review the identity source and private membership provisioning, implement each app BFF callback/session store, register exact HTTPS redirects and app service keys, deploy reviewed migrations, verify revocation/profile switch/outage behavior against both apps, and record live issuer/release evidence. The legacy Agent web JWT and run token are not accepted. No production route or deployment is enabled by this change.

The source audit and proposed handoff protocol are tracked in [CONNECTED-APP-PROFILE-AUTHORITY-GATE.md](CONNECTED-APP-PROFILE-AUTHORITY-GATE.md).
