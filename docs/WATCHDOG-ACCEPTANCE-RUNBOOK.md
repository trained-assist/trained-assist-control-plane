## Что доказываем

Единственный непроверяемый элемент класса «сообщение принято, но дальше тишина»:
**внешний детектор действительно находит вход, уведомление действительно доходит,
пользователь может выполнить предложенное действие, а повторное нажатие не создаёт
второй запуск.**

Всё остальное закрыто тестами: инвариант буфера (tg-bot#346), дедлайн старта и оба окна
(#33/#35/#36), планировщик и адаптер (#38), seam-стык (#38 + tg-bot#347).

## Шаги

### 1. Миграции на боевую (песочничную) D1

```
npx wrangler d1 migrations apply ta-cp23-sandbox-taskstore --remote
```

Ожидание: применены 0009 (`pending_inputs`, `stuck_input_alerts`), 0010 (бэкфилл
`start_deadline_at` для pre-start строк с NULL), 0011 (`watchdog_health`).

Проверка:

```
npx wrangler d1 execute ta-cp23-sandbox-taskstore --remote \
  --command "SELECT name FROM sqlite_master WHERE type='table' AND name IN
             ('pending_inputs','stuck_input_alerts','watchdog_health')"
```

Откат: D1-миграции не откатываются. Откат — redeploy предыдущего коммита воркера
(код терпим к отсутствующей таблице: watchdog при отсутствии `watchdog_health` просто
не пишет отметку) плюс ручное удаление строк, созданных приёмкой.

### 2. Деплой control plane с cron-триггером

```
npx wrangler deploy
```

`wrangler.jsonc` объявляет `triggers.crons = ["* * * * *"]`. Проверка:

```
npx wrangler triggers
# scheduled: * * * * *
```

Откат: `npx wrangler rollback` или redeploy предыдущей версии.

### 3. Обвязка доставки

| Переменная | Значение |
|---|---|
| `DELIVERY_ADAPTER` | `gateway` |
| `GATEWAY_DELIVERY_URL` | публичный URL tg-bot (`https://trained-assist-tg-bot.<subdomain>.workers.dev`) |
| `GATEWAY_DELIVERY_SECRET` | тот же `AGENT_SECRET`, что у шлюза |

`DELIVERY_ADAPTER=gateway` без `GATEWAY_DELIVERY_URL` — намеренная ошибка, а не тихая
подмена заглушкой: иначе доставка выглядела бы успешной, а пользователь ничего не получил бы.

### 4. Приёмка — основной сценарий

| # | Шаг | Ожидание |
|---|---|---|
| 1 | Отправить в группу текстовое сообщение, дождаться квитанции накопителя | кнопка ▶️ есть |
| 2 | **Намеренно отключить аларм накопителя** (снять/сломать таймер DO) и оставить VM выключенной | — |
| 3 | Дождаться `start_deadline_at` | — |
| 4 | Дождаться прохода планировщика (≤1 мин после дедлайна) | в `watchdog_health` свежая `last_run_at`, `scanned ≥ 1` |
| 5 | Проверить чат | уведомление с живой кнопкой ▶️ **реально пришло** (не «доставлено» без `providerMessageId`) |
| 6 | Нажать ▶️ | задача запустилась, ответ пришёл |
| 7 | Нажать ▶️ ещё раз на той же кнопке | **второго запуска нет** (буфер пуст / ран идёт) |
| 8 | Проверить outbox | одна строка на `logical_message_id`, `status='delivered'`, `provider_message_id` заполнен |

Шаги 2 и 3 — суть проверки: сломанный/отсутствующий таймер накопителя **не должен**
оставлять вход невидимым.

### 5. Приёмка — сбои и границы

| # | Сценарий | Ожидание |
|---|---|---|
| A | Доставка недоступна (шлюз 5xx) | `delivery_state='pending'`, повтор с backoff, **не** «успех» |
| B | Шлюз отвечает 200 без `providerMessageId` | доставка **не засчитывается** |
| C | Неверный `GATEWAY_DELIVERY_SECRET` | доставка не «успешна», остаётся повторяемой |
| D | Медиа приходит позже дедлайна | `waitKind=media_prep`, `warn`, оператор **не** алертится |
| E | Новый вход во время проверки | возраст **самого старого** непродвинувшегося виден; `first_message_at` не перебивается |
| F | Run уже начался | запись не доставляется и не алертится (`skippedStale`) |
| G | Backlog больше одной страницы | обходятся **все** просроченные, не только первые 50 |
| H | Планировщик остановлен | `intake.watchdog_scheduler_stale` в логах, отметка устаревает |
| I | Группа (отрицательный chat id) | адрес доставки сохраняется, доставка подтверждена |

### 6. Контроль работоспособности планировщика (П3c)

Отметка пишется **только после успешного прохода**. Сбой прохода не должен выглядеть как
«всё в порядке»:

```
npx wrangler d1 execute ta-cp23-sandbox-taskstore --remote \
  --command "SELECT last_run_at, scanned, delivered, alerts FROM watchdog_health WHERE id=1"
```

Независимая проверка (внешняя к планировщику) алертит, если отметка старше 30 минут.

Пройдено = шаги 4.1–4.8 и сценарии A–I выполнены с указанными исходами, **с

`deliveries`). Зелёные юнит-тесты этого не заменяют: до шага 4 «проверено сквозным» —
